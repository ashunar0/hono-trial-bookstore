# Questions

設計書を読んでもわからなかったこと。止まらずに、おすすめの方で進めた。

## point（段 1）

- QUESTION: 「データベース」タブは、ポイントの残高を `INSERT … ON CONFLICT DO UPDATE` の「無ければ作る」形で書くとあるが、そのままだと使う（負の増減）が通らない。SQLite は ON CONFLICT を見る前に、INSERT しようとする行（残高 = −200 など）に CHECK (balance >= 0) をかけるので、残高が足りていても落ちる。おすすめの方で進めた: 履歴の INSERT → 残高の行を 0 で作る（`ON CONFLICT DO NOTHING`）→ 残高を UPDATE で足し引き、の 3 文を 1 つの batch に。残高が足りなければ UPDATE の CHECK で batch ごと取り消され、残高の行が無い客が使っても同じく取り消される。設計書の書き方を直してほしい。

## 注文の確定（段 2）

- QUESTION: ポイントの割り振りの端数。「概要とルール」の例は、本 1,000 円＋送料 550 円を 500 ポイントで払うと「本に 323、送料に 177」。でも「データベース」タブは「送料をいちばん最後の行とみなし」、概要の割り振りは「端数は最後の行に寄せる」とある。送料が最後の行で端数を受け持つと 322 と 178 になり、例と合わない。おすすめの方で進めた: 例の数字を正として、送料を含む全員が切り捨て、端数は最後の本の行が受け持つ（送料が 0 円でも同じ形になる）。設計書の文を直すか、例を 322 と 178 に直すかを決めてほしい。
- QUESTION: 使ったポイントを戻すとき、order は「使った量」を渡すのか、point が使用 id から読むのか。使う前に確定が止まった注文（cron が「確定中」からキャンセルする）で、order が量を渡す形だと、使っていないポイントが戻って湧いてしまう。おすすめの方で進めた: 注文まるごとの戻し（キャンセル・確定の取り消し）は `restorePointsOfUse(useId)` にして、point が使用の履歴の行から量を読む（無ければ何もしない）。返品の一部は order が量を渡す `restorePoints`（戻しの id は返品 id から決まる）。設計書の usecase 名は「戻す」の 1 つだが、2 つに分けた。
- QUESTION: 確定が「支払い済み」で終わる（全部ポイント）とき、`paidAt` を確定の時刻にした。設計書に書いていなかった。
- QUESTION: orders の `earn_id`（貯める id）は nullable にした。NOT NULL で足す列に既定値が無いと、SQLite は ALTER TABLE ADD COLUMN を受けつけない（空の表でも）。ポイントができる前の注文は null で、貯める cron は飛ばす。設計書は「貯める id も作って保存」とだけある。
