# Questions

設計書を読んでもわからなかったこと。止まらずに、おすすめの方で進めた。

## point（段 1）

- QUESTION: 「データベース」タブは、ポイントの残高を `INSERT … ON CONFLICT DO UPDATE` の「無ければ作る」形で書くとあるが、そのままだと使う（負の増減）が通らない。SQLite は ON CONFLICT を見る前に、INSERT しようとする行（残高 = −200 など）に CHECK (balance >= 0) をかけるので、残高が足りていても落ちる。おすすめの方で進めた: 履歴の INSERT → 残高の行を 0 で作る（`ON CONFLICT DO NOTHING`）→ 残高を UPDATE で足し引き、の 3 文を 1 つの batch に。残高が足りなければ UPDATE の CHECK で batch ごと取り消され、残高の行が無い客が使っても同じく取り消される。設計書の書き方を直してほしい。

## 注文の確定（段 2）

- QUESTION: ポイントの割り振りの端数。「概要とルール」の例は、本 1,000 円＋送料 550 円を 500 ポイントで払うと「本に 323、送料に 177」。でも「データベース」タブは「送料をいちばん最後の行とみなし」、概要の割り振りは「端数は最後の行に寄せる」とある。送料が最後の行で端数を受け持つと 322 と 178 になり、例と合わない。おすすめの方で進めた: 例の数字を正として、送料を含む全員が切り捨て、端数は最後の本の行が受け持つ（送料が 0 円でも同じ形になる）。設計書の文を直すか、例を 322 と 178 に直すかを決めてほしい。
- QUESTION: 使ったポイントを戻すとき、order は「使った量」を渡すのか、point が使用 id から読むのか。使う前に確定が止まった注文（cron が「確定中」からキャンセルする）で、order が量を渡す形だと、使っていないポイントが戻って湧いてしまう。おすすめの方で進めた: 注文まるごとの戻し（キャンセル・確定の取り消し）は `restorePointsOfUse(useId)` にして、point が使用の履歴の行から量を読む（無ければ何もしない）。返品の一部は order が量を渡す `restorePoints`（戻しの id は返品 id から決まる）。設計書の usecase 名は「戻す」の 1 つだが、2 つに分けた。
- QUESTION: 確定が「支払い済み」で終わる（全部ポイント）とき、`paidAt` を確定の時刻にした。設計書に書いていなかった。
- QUESTION: orders の `earn_id`（貯める id）は nullable にした。NOT NULL で足す列に既定値が無いと、SQLite は ALTER TABLE ADD COLUMN を受けつけない（空の表でも）。ポイントができる前の注文は null で、貯める cron は飛ばす。設計書は「貯める id も作って保存」とだけある。

## 支払いの額（段 3）

- QUESTION: このアプリには支払い API の呼び出しが無い（`pay` は「支払った」ことにするだけ）。「支払い API に渡す額 ＝ 合計 − 使ったポイント」をどこに出すか書いていなかった。おすすめの方で進めた: `amountToPay`（order/rules.ts）で計算し、`payOrder` が `{ order, charged }` で返す。HTTP のレスポンスには出さない（注文の `total` と `pointsUsed` から計算できる）。本物の決済をつなぐときは `charged` を渡す。

## キャンセル（段 4）

- QUESTION: 支払い待ち（カードを払う前）のキャンセルで、ポイントを使っていたら返金の行を作るか。設計書は「支払い済みなら合計の全額の返金を記録する」とだけ。おすすめの方で進めた: 返金の行は作らず（払っていないので）、ポイントは使用の履歴から全部戻す。支払い済み（全部ポイントで払った注文も含む）は返金の行を作り、`points_amount` に使ったポイント、残りがカード。

## 返品の受け取り（段 5）

- QUESTION: 返金の `amount`（返すお金）は、ポイントで払った分も含めた「本の値段 − 割り振った値引き」のままにして、`points_amount` にポイントで戻す分を持った（カードに戻す分は `amount − points_amount`）。設計書の「返すお金・うちポイントで戻す分・うち消費税」の読み方がこれで合っているか。例: 1,600 円の本 1 冊の返品は amount 1,600、points_amount 250、カードは 1,350。
- QUESTION: 返品でポイントを戻す量は、本に割り振ったポイントを「1 冊あたり切り捨て、最後の 1 冊が残りを持つ」で分けた（値引きと同じ）。返品の受け取りの順番が違っても、全部返せば割り振ったポイントちょうどになる。

## ポイントを貯める（段 6）

- QUESTION: 返品の受付期限ちょうどの時刻は、返品を受け付ける（`now > 期限` で断る）ので、貯める cron も `shippedAt < now − 14 日`（期限ちょうどは拾わない）にした。設計書の cron の表の注意書きと同じ読み方。
- QUESTION: 「申請中の返品がある注文は飛ばす」とき、cron は何も書かない（ok を返す）ことにした。却下か受け取りで片付いたあとの回で拾い直す。却下された返品だけの注文は、通常どおり貯まる。
- QUESTION: 貯める元の「返品で返したお金の合計」は、返金のうち返品のもの（`return_id` がある行）の `amount`（ポイントで戻した分も含む）にした。ポイントで払った分にも貯まる、という設計書の文と同じ向き。
- QUESTION: 締めと返品の申請が同時に来たときの「どちらか一方が 409」は、`updateOrder` の version で成り立つが、読んだあと書く前に割り込ませるテストは書けなかった（db を差し替えるやり方が、`updateWithVersion` の中の呼び方に依る）。version が 1 進むことだけテストにした。
- QUESTION: 貯める cron の置き場所。別のファイルにせず、`src/crons/sweep-orders.ts` に足した（式が同じ 15 分ごとで、設計書の cron タブも 1 つの cron として書いている）。
